# M7: deterministic threading and stored-node crouch tests

The fastest measured Stage-A warm Map A BSP run is 59.22 seconds at 8 threads, versus 119.55 seconds for the M6 warm run at that setting (2.02x). Stage B takes 49.20 seconds on its separate 16-thread warm run. These are individual measurements, not a statistical benchmark.

Stage A preserves M6 NAV bytes for all four acceptance cases at 1 and 16 threads, and for Map A BSP at 4 and 8 threads. Its complete source snapshot is kept under `work/m7/stage-a/`. Stage B is the separate crouch correction. Native acceptance is separate.

The baseline is commit `536b293ad6071a9be51561c03c89d508b1fbc19f`. Runtime changes in A are compiled collision-vector work, ordered speculative sampling, parallel rectangle pre-tests, parallel stairs/connection/hiding probes, exact per-worker trace counters, compiled-code caching and `--threads`. The graph-edit order is unchanged. Fence-top construction has no collision probes to move into workers and stays sequential. Stage B changes only sampling/crouch behavior, its regression test and README relative to the frozen A tree.

The collision code preserves hull/triangle and plane order, with no fast-math transformations. The convex/triangle helpers matched the old plane bytes on 400 randomized inputs; the complete Map A collision-array hashes also match M6. Source and input hashes were checked around every generation. Four-map NAV equality is the output acceptance criterion.

Sampling precomputes pending directions on the existing DFS frontier, keyed by exact origin bits and direction. Each sequential chunk consumes available results and computes misses directly; visiting, parent, reciprocal-link and commit rules remain unchanged. The bounded memo holds 262,144 results and looks through up to 512 ancestors between 512-attempt chunks. In the final Map A run, 167,512 of 1,071,509 lookups hit (15.63%); 654,161 jobs were computed, of which 25.61% were consumed. Unused probes still count in exact trace totals. This limits sampling speedup; the overall gain does not imply every phase is faster.

Each rectangle size gets a parallel pre-test against the start-of-step owner state. The original reverse-node claim loop then rechecks ownership only. Other graph edits retain their existing sequential order. Connection and hiding results are applied in their original area/link order. Worker counters occupy separate padded slots and are summed after parallel work.

Timings below are seconds on the Ryzen 7 9800X3D (8 cores / 16 logical threads), Python 3.10.11, NumPy 2.2.6, SciPy 1.15.3, Numba 0.63.1, llvmlite 0.46.0 and the OMP threading layer. The final before/after matrices ran sequentially, without other navgen jobs. Earlier development measurements remain under their original labels and are excluded. Collision and sampled-array hashing is included in phase timings; source/input file hashing is outside them. Node snapshots add compression overhead to captured first runs; warm timing runs do not capture snapshots. Input parsing takes about 0.1 seconds and is included in Total. Every individual graph pass is also recorded in JSON.

M6 has no persistent compilation cache: cold is a fresh process, warm repeats in the same process after compilation. Stage-A cold uses a new empty compiled-cache directory; its warm run is a new process loading that directory. These are Numba/JIT cache states, not claims about the operating system file cache.

Peak memory is the Windows process peak working set; the M6 warm repeat includes its earlier cold peak. Peak pagefile commitment is retained in JSON. Performance depends on geometry and cache state; the earlier 35–45 second estimate is not an acceptance claim.

The cache stores compiled code under a package-source/dependency-version namespace beside the sources (or beneath `NUMBA_CACHE_DIR`). This addresses Numba's documented failure to detect changes in imported symbols. A fresh-process regression warmed an importing caller, changed its collision helper at the same file size and timestamp, then confirmed a new namespace and the changed floor result. Warm CLI logs record cache loads and no new compiled data writes. A direct-library cold/warm subprocess test also covers backend initialization before cached trace code calls `get_thread_id`; the runtime initializes it through the public API. The initial pre-fix snapshot and measurements are retained under `before-cache-init` and excluded from the final timings. CPU/Python compatibility remains Numba's responsibility. Restart after source edits. See [Numba caching](https://numba.readthedocs.io/en/stable/developer/caching.html) and [thread controls](https://numba.readthedocs.io/en/stable/user/threading-layer.html).

Stage B evaluates each completed node once at `pos[node]`, in a parallel batch after sampling. Crouch and blocked flags only become true; ground heights are rewritten. No sampling decisions use those flags before this batch, and collision/positions remain static, so this equals repeated sticky `CheckCrouch` calls at the stored node position. Incoming step points no longer overwrite existing nodes' corner state. Node positions, normals, links, parents, visited bits and obstacle measurements match Stage A.

This follows [Valve SDK revision be57e3d](https://github.com/ValveSoftware/source-sdk-2013/tree/be57e3d01ac7d7aa6a2cacbfef187c0b46616db0), `nav_node.cpp` 278–394 and `nav_generate.cpp` around 4130. Read-only disassembly confirms the installed binary: AddNode passes the resolved node at `0xc4f22`/`0xc4f25`; CheckCrouch at `0xd4c30` only writes true after a failed standing test (`0xd4e6a`–`0xd4e78`); TestForCrouchArea at `0xd5840` reads stored position at `0xd58d8`/`0xd58ee`. The DLL SHA-256 is `cac5a957b6589c71760b37406b6b99604a49025f67fd6e14c902aa6e1ef63428`; it was never loaded or executed.

4 of the 4 Stage-B acceptance NAVs remain byte-identical to M6. The synthetic low-ceiling fixture demonstrates the behavior change directly: a stored node at Z=5 requires crouching, while an incoming point at Z=0.03125 incorrectly cleared its four crouch flags in Stage A. Stage B preserves those flags. Exact per-map corner and geometry changes are listed above.

All Stage-B coverage/transition nonregression checks: **passed**. The JSON comparisons retain exact scores and directed-transition counts. Coverage uses 25-unit centers and an 18-unit height tolerance; transition scores exclude shared internal subdivisions and long gaps. Map B's reference is a different BSP revision, and historical A-old seeds intentionally add floors outside the BSP-seeded engine reference. These metrics do not establish native traversal.
