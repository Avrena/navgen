# M5: fixed displacement collision winding

M5 uses the SDK's fixed displacement triangle winding. It corrects inverted side=1 terrain and preserves triangles folded away from their base plane. All 42 tests pass. Four fresh CLI runs completed with hiding analysis; Construct is byte-identical to M4.

For Map A with BSP seeds, coverage precision/recall against the same-BSP engine mesh changes from 98.537% / 96.597% to 99.869% / 98.667%. Removing hiding data and restoring analyzed=0 reproduces an independently generated experimental NAV byte for byte.

This work used offline Python and read-only SDK/engine/map inputs; earlier native results are attributed separately below.

## SDK verification and code change

The inspected Valve Source SDK commit is `be57e3d01ac7d7aa6a2cacbfef187c0b46616db0`. Raw source hashes and exact line ranges are recorded in `measurements/m5/source-evidence.json`.

- [DispMapToCoreDispInfo](https://github.com/ValveSoftware/source-sdk-2013/blob/be57e3d01ac7d7aa6a2cacbfef187c0b46616db0/src/utils/vbsp/disp_vbsp.cpp#L147) copies the original face winding and rotates it to the displacement start corner. [VBSP face writing](https://github.com/ValveSoftware/source-sdk-2013/blob/be57e3d01ac7d7aa6a2cacbfef187c0b46616db0/src/utils/vbsp/writebsp.cpp#L465) stores the already oriented plane index, side=planenum&1, and consecutive face vertices as surfedges. The side byte does not call for another displacement-front reversal.
- [CCoreDispInfo](https://github.com/ValveSoftware/source-sdk-2013/blob/be57e3d01ac7d7aa6a2cacbfef187c0b46616db0/src/public/builddisp.cpp#L896) builds a checkerboard index pattern. Its odd grid width makes vertex-index parity equivalent to x+y parity. CreateTris copies these indices into collision records. GenerateDispSurf builds the flat grid and then adds sculpted offsets; folding does not change those indices.
- [CDispCollTri::CalcPlane](https://github.com/ValveSoftware/source-sdk-2013/blob/be57e3d01ac7d7aa6a2cacbfef187c0b46616db0/src/public/dispcoll_common.cpp#L81) computes `(v2-v0) × (v1-v0)` directly. There is no realignment to the base normal. The Python kernel uses the opposite cross-product convention, so `BSP.displacements()` now swaps indices 1 and 2 once. Triangle order, tags and removed-triangle handling remain intact.
- [Ray intersection](https://github.com/ValveSoftware/source-sdk-2013/blob/be57e3d01ac7d7aa6a2cacbfef187c0b46616db0/src/public/collisionutils.cpp#L66) culls normal·delta ≥0 when one-sided. The displacement ray API defaults that mode to true and passes v0,v2,v1. [Swept AABB tests](https://github.com/ValveSoftware/source-sdk-2013/blob/be57e3d01ac7d7aa6a2cacbfef187c0b46616db0/src/public/dispcoll_common.cpp#L1331) cull normal·delta >0.03125. The existing Python SAT/tolerance approximation is unchanged; this milestone corrects orientation.

The direct SDK index swap agrees with an independent undisplaced-grid rule on every emitted triangle in all three BSPs. The frozen M4 code fails the new side=1 and folded-triangle regressions; M5 passes them, including front/back rays and hulls. Other new tests check checkerboard diagonals, all four start-corner rotations and removed-triangle tag alignment.

Exact command:

```text
.venv\Scripts\python.exe -I -B -m navgen map_a.bsp --out work\m5\map_a.nav --slope-limit 0.55 --seeds work\m2\component-seeds.txt
```

42 tests passed in 25.848 seconds. All four new NAVs round-trip exactly, their BSP sizes match, and input/content-selection checks agree with M4. Each CLI record contains source hashes, exact arguments and input/output hashes.

Remaining limits include the unverified links above, fitted-area/traversal differences, collision tolerances, static content/mount and entity-state differences, and runtime/Lua geometry. The generator still omits ladders, places, teleport links, encounters and visibility; light remains 1 and occupy times 0 for the implemented quicksave=2 analysis mode.
