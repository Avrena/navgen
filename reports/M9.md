# M9 — conservative SDK area merging

Offline candidate for native review. Default SDK output is byte-identical to the preserved 62dee41 baseline on all four cases at both 1 and 16 threads. All 78 current tests pass. The merged profile reduces area count in all eight comparisons while retaining exact XY coverage and the 0.5-unit original-corner bound.

All 360 main/upper model comparisons have matching complete/partial flags and length differences below 5%. The stricter exploratory 3% target was **not** met: seeded main route 49 differs by about 4.3%, with and without entity discovery. This is disclosed as a native-test risk, not a claim of route-for-route gameplay parity.

## Implementation and defaults

`--profile sdk` remains default. `--profile merged` first builds the same SDK mesh, then contracts rectangles with a complete shared edge and reciprocal links in the correct compass directions. Attributes, places and corner-light tuples must agree. Both plane normals must be compatible (dot ≥0.99), shared-edge heights must agree within 0.5, and **all original corners** must remain within 0.5 units of the merged bilinear surface across chained merges. There is no XY gap allowance. The generic merged-side limit is 125 units; existing larger SDK areas are kept as they are.

NO_MERGE (8192), TRANSIENT (256), NAV_BLOCKER (0x80000000), blocked/damaging records, explicit locks and ladder attachments cannot merge. Known static trigger-hurt, nav blocker/avoid/cost, and water brush volumes conservatively lock intersecting areas, including disabled sources whose runtime state is unknown. Water classification uses the SDK ground probe plus world BSP leaf contents at ground+1; changed centre classification rejects a merge. Runtime changes and arbitrary Lua-created hazards are outside offline evidence.

Every removed shared edge receives reciprocal movement probes. Every affected incoming and outgoing frontier receives a fresh SDK movement/drop/portal witness; merging also preserves the native 18/58/-200 height classes. The final directed graph equals the original graph with each group contracted, including stored compass directions and one-way edges. Hiding is recomputed using the existing nav_quicksave 2 implementation after all merges.

`--seed-discovery entities` is opt-in on both profiles; default `none`. `--ladders` is separately opt-in on both profiles; default off. All eight staged merged candidates contain zero ladders. The explicit SDK ladder CLI check wrote 15 validated records and passed serialization/reciprocal-reference checks. That check establishes format and geometry witnesses only, not stock NextBot ladder use. The prior native run loaded 16 M8.1 ladders but had ladder route failures, which is the reason for the default change.

The retired M8.1 fine flood, fitting, refinement and pruning modules and their obsolete tests were removed after preserving their exact source in `work/m9/baseline`. Small hull/floor helpers remain for entity seeds and optional ladders; the previously compared native path model remains unchanged. Package modules fell from 28 / 4,448 lines to 21 / 3,263 lines. Existing SDK implementation modules match HEAD; only its CLI gains profile/option integration. The final reproducible snapshot has 42 source/configuration files.

## Geometry and links

An independent audit checks that each merged rectangle contains disjoint original rectangles whose summed XY area equals it. This establishes the exact union, including holes remaining outside groups. Every original corner is checked against the serialized result. On each original rectangle the difference between bilinear surfaces has extrema at corners, so the reported height bound applies throughout, not just at sampled centres. These preserve the **SDK surface convention**; they do not correct or re-prove SDK coverage/height against native collision.

The complete flag means path construction reached its goal area; a valid partial path can still have a length and end at an unreachable goal in the path details. It does not mean a native bot reached the goal.

Additional short probes cross merged original-area boundaries on every case/mode: gm_construct none: 20/20 flags equal; gm_construct entities: 20/20 flags equal; Map B none: 20/20 flags equal; Map B entities: 20/20 flags equal; Map A BSP seeds none: 20/20 flags equal; Map A BSP seeds entities: 20/20 flags equal; Map A + A-old seeds none: 120/120 flags equal; Map A + A-old seeds entities: 20/20 flags equal. The staged `routes_merged.json` contains 120 routes in harness form `[sx,sy,sz,gx,gy,gz,timeout,reach]`: 60 spatially distributed seeded-Map A merged groups, both directions. Both endpoints lie on both meshes; their metadata includes area IDs, lengths, complete flags and expansions. Selection is deterministic. These probes remain untested in game.

The unchanged native model was also compared with run8's 126 recorded `sdkrq` routes on the 31,764-area SDK mesh: 124/126 complete flags agree; maximum relative length difference is 1507.09%. This wider check exposes a material scope limit. Ladder fixtures 33/34 report native `complete=false` with about 12,266 units of path, while the model selects the same SDK area for both unsupported endpoints and returns `complete=true`, 0.77 units. Fixture 26 has a requested start outside its nearest SDK rectangle; native length is 6 versus modeled 96.43 units. Requested coordinates do not capture the bot's actual grounded position or engine-selected areas; nearest-area LOS and placement are omitted. These observations prevent treating the model as a universal native oracle.

For diagnostic context only, the 68 historical routes with both XY endpoints in their nearest SDK rectangles and height errors ≤4.5 at start / ≤0.5 at goal have 68 matching complete flags and maximum length difference 5.37%. All 126 records, including every failure, remain in `native-run8-sdk.json`; none were dropped from the overall comparison. The new 120 fixtures require endpoints on both meshes, but still need native bot testing. These are historical SDK observations, not observations of M9.

CLI measurements run sequentially from the frozen snapshot. The warm SDK run is excluded. A first merged CLI run can include compilation of newly used helpers; the isolated repeats use matching cached SDK controls and separately time merging/environment and hiding. Reported merging time includes reading area semantics and water probes, but excludes collision construction and SDK generation. Full CLI phase timings and commands remain in `final-*.json`.

The entity-seeded Map A full CLI sample took 11.217 seconds in the merge phase, slightly above the roughly ten-second aim; its isolated repeat took 4.217 seconds. The other full CLI merge phases were below ten seconds. The different samples do not prove the cause of that variation, and a universal ≤10-second guarantee is not claimed.

The optimizer's permissive 800-side pairwise candidate reduced Map A BSP to 13,861 and seeded to 25,550, but moved a modeled route by 20.7%; it was rejected. A 200 limit still reached 7.7%, and 150 exceeded the tighter exploratory 3% target. A 100 limit retained fewer reductions yet changed main route 18 by 3.6%. The selected 125 limit gives a more useful size reduction while all 60+30 route differences stay below 5% after fresh link checks. No route IDs or fixture coordinates are hard-coded into production merging.

A tolerance trial at 1.0 instead of 0.5 gained only two additional seeded areas before the final shared-edge checks; it was rejected. An unchanged-gateway prototype gave only about 2–3% reduction and still changed paths. Maximal flat re-tiling is not part of this candidate: even simple larger merges already changed native centre costs and portal choices substantially. Exact surface union alone does not establish path parity. Full trial summaries and the preserved implementations are available for review.

## Reproduction and acceptance

Use the repository virtual environment with isolated Python, explicit staging output, and a frozen source snapshot. `work/m9/final_tests.py` runs the 78 tests. `final_matrix.py` records the 4×2 SDK parity runs, all eight merged CLI runs, and a separate ladder opt-in run. `final_audits.py` repeats matching-control contractions, checks geometry and every link, runs route models, and produces the 120 native fixtures. `final-source/source_sha256.json` fixes the tested source; exact CLI argv is in the measurement records. Reproduction requires the original local read-only BSP/game assets and earlier SDK controls; those assets are not redistributed.

Staged no-discovery candidates:

- `work/m9/gm_construct-merged.nav`
- `work/m9/map_b-merged.nav`
- `work/m9/map_a-bsp-merged.nav`
- `work/m9/map_a-merged.nav`

Matching `-merged-entities.nav` files stage the opt-in discovery variants. `work/m9/routes_merged.json` and `routes_merged_meta.json` stage the bounded native checks.

Native acceptance remains pending: route-for-route main 52/60 and upper 28/30 results, no new stuck routes, and measured lower load/replace times. The 4.3% route-49 difference and inherited SDK exceptions should remain visible during that review.
