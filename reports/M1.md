# M1: offline Python NAV generator

M1 is an executable offline draft, with measured comparisons and staged NAVs. The offline acceptance work is complete. Native loading and NextBot traversal are untested; matching native coverage is not established on both reference maps. Map A, Map B and Map C are private test maps; A-old is an earlier revision of Map A.

The implementation reads BSP/game content and writes only the NAV output.

## What is implemented

- `python -I -m navgen <map.bsp> [--game <directory>] [--out <file.nav>] [--seeds <file>] [--missing-phy bbox|skip]`. Default game is the local GMod directory; default NAV is beside the BSP. Output is validated and atomically replaced. Exact input byte size is written to `bspSize`; failures return nonzero. See `README.md` for setup and quoted Hammer++ arguments.
- BSP v20 geometry, Valve LZMA lumps, BSP-node/leaf brush membership, bevel planes, brush contents and surface flags. Brush entities use their initial origin/angles, solidity, transparent/MOVEABLE filtering, and generation walkable rules for doors, breakables, toggle brushes, `func_physbox` and `func_pushable`.
- Contents-aware swept AABB traces compiled with Numba. Convex hulls use face, axial and supported edge bevel planes; a BVH accelerates object selection. Traces return fraction, normal, start/all-solid, contents, displacement, surface flags and object ID. Flat PHY ledges are supported.
- Static prop MDL/PHY lookup in BSP pakfile, unpacked addons, GMod and Source-engine VPKs, then loose folders. SOLID_BBOX uses a world-axis-aligned MDL hull; SOLID_VPHYSICS uses rotated/scaled PHY convex pieces. Default missing-PHY policy is a transformed MDL hull box; `skip` is available. Missing MDLs are reported and skipped.
- Displacement grid reconstruction, SDK checkerboard triangulation, REMOVE-tag omission, and one-sided triangle SAT traces. Non-removal walkable/buildable tags are not treated as separate collision channels; generated slope checks use collision normals.
- Seeds from all `info_player_start` entities, targets of `trigger_teleport`, and optional text coordinates. Each seed snaps to the 25-unit XY grid and is grounded. Teleport targets seed disconnected floors; no teleport traversal link is serialized.
- Cardinal node sampling, step/climb, overlap rejection, displacement embedding tests and quadrant crouch checks; greedy closed-cell rectangles; reciprocal/drop connections; jump marking; merging; overhang splits; square-up; stairs; jump stitching/removal; raised and one-/two-node fence tops; overlapping-fence removal; corner helpers; stair-side/redundant-link corrections; final collision pruning.
- v16/subversion 0 serialization, `analyzed=0`, empty tactical/ladder data, light 1, occupy times 0. The supplied NAV reader/writer was retained and validated on five existing engine files.

Constants: grid 25, thin hull ±0.45 XY / 55 high, overlap half-height 35.5 / full height 71, step 18, crouch-jump 64, maximum climb 200, drop 400, slope 0.7, greedy area limit 50 cells per axis, fence minimum width 10, displacement test 10000. Float64 collision and explicit tolerances are used; no fast-math or parallel reductions.

### Reference comparison

Coverage samples world-grid cell centers every 25 units, matching floors within 18 units. Same-XY floors are retained; near-identical samples are deduplicated by Z rounded to one unit. Scores compare the available reference data, not an independently established walkable-surface truth.

**gm_construct:** the reference BSP byte size matches. Of 15,665 missed cells, 15,253 lie in the other eleven disconnected reference components; the largest reference component misses only 412 of 143,484 cells, or 99.713% recall there. This supports seed/reachability differences as the main explanation for the overall recall gap. It does not prove the cause of every missing island: the reference has one ladder and may include hand edits or extra seeds. The missed-floor probes mostly find supporting geometry; a point ray does not test player clearance or reachability. No reference-derived seeds were added to improve the score.

**Map B:** the reference records an older BSP byte size; known repacking does not establish a geometry change. 514 MDLs are unresolved, affecting 2,448 solid prop instances, and 146 more solid instances have the bbox fallback. Omitted collision can overgenerate walkable coverage and links. 63,817 missed cells lie inside the largest reference component, so isolated reference islands cannot explain this map's deficit. Model mounting, hull approximations, sampling, seeds, historical settings and edits remain candidate causes; the comparison has not separated their contributions. The current scores are insufficient to claim native coverage parity.

Directed metrics examine cardinal neighboring cells on common coverage when either mesh crosses an area boundary. They exclude shared internal cells and long jump/drop gaps; overlapping-area ownership can also be ambiguous. The very high conditional scores must **not** be read as whole-mesh link agreement. Weak/strong component counts expose additional connectivity differences. Final wall checks use the same portal/movement rule that pruned generator links, so zero failures show consistency only; they are not evidence of engine collision correctness.

## Offline validation

- 13 unittest cases passed in 23.842 seconds. These include 1,500 deterministic randomized swept-hull comparisons between BVH and all-object tracing across 35 rotated convex shapes and 35 displacement triangles; analytical fractions/normals, start/all-solid and masks; one-sided terrain and flat PHY ledges.
- End-to-end low-ceiling room coverage/crouch attributes; allowed one-way 250-unit drop and rejected reverse climb; high-wall rejection; overhang links to exposed lower area; direction-preserving jump stitching; fence deletion with no dangling links; a directed comparison fixture that detects a missing reverse link.
- Byte-identical read/write on `gm_construct`, `gm_flatgrass`, `map_b`, `map_a_old`, `map_c` engine NAV files. Each newly generated NAV is also parsed/re-encoded byte-identically and checked for finite geometry, nonempty unique IDs and valid directed targets.
- Every Map A static-prop model was examined and every available PHY parsed during the complete run. This proves parser coverage for these files, not engine-equivalent contact behavior.
- The real CLI ran from a working directory with spaces using BSP, seed and output paths with spaces. Its NAV was byte-identical to the measured gm_construct output. Missing input and invalid seeds returned nonzero, and invalid seeds left the existing NAV unchanged. This checks the command line, not Hammer's UI.

## Known gaps and deliberate differences

1. **No native acceptance.** Python collision is not an engine trace oracle. VPhysics contact tolerances, coplanar hits, PHY multi-solid/bone poses, displacement seams and hit ordering need independent engine traces. BVH-versus-brute-force tests share the narrow-phase kernel.
2. **Content and runtime state.** Search order is explicit and deterministic, not the engine's live mount order. GMA/workshop archives, Lua-spawned props, game state, dynamic doors and animation are absent. Missing MDLs are skipped with names/counts; bbox fallback may block space differently. Non-brush model entities are excluded entirely, including the NPC-mask stair probes; that latter case is a fidelity gap.
3. **Approximate SDK details.** Spawn-pose rotated brush geometry is rebuilt; per-face surface flags on those rebuilt hulls are not retained. Corner helpers and stair-side connection correction are geometric adaptations. Node reuse tolerance/order, floating point and tie ordering can change partitions. Adjacent-step recursion has a 64-step guard. Jump stitching deliberately does not span arbitrary chains of jump areas. The generic final portal check is an extra conservative pass, potentially removing valid native links.
4. **Fence/overhang corrections.** Public SDK fence code contains suspicious assignments/fallthrough/early return behavior; this implementation uses measured start/end distances, both endpoint heights along the correct tangent axis, continues across areas, and reconnects the exposed lower child after an overhang split. These are deliberate corrections, not claims of byte-equivalent GMod behavior. SDK-style obstacle overlap cleanup is XY based and removes smaller/contained overlaps rather than building a union.
5. **Deferred features.** Ladders, hiding/encounter/sniper/visibility analysis, places, meaningful lighting/occupancy and runtime traversal links are absent. `analyzed=0` is intentional. Some maps require additional seeds. Teleport-target seeding does not make teleporters traversable through ordinary NAV links.
6. **Supported formats.** Measured on these BSP v20 / NAV v16-0 / compact-ledge PHY inputs. Compressed static-prop game lumps and unknown solid/surface types are unsupported; unknown static-prop solidity is reported. This is not a hardened parser for arbitrary hostile files. Hammer++ profile UI has not been exercised.

## Follow-up native checks (outside M1)

In a native test session, keep the installed mesh and load a staged NAV whose BSP size matches the final packed BSP. Check the engine accepts v16/0 and all links, then exercise NextBot paths through ordinary doors, always-solid/toggle brushes, breakables, crouch corridors, stairs, displacement seams, scaled/rotated props, narrow fences, one-way drops and teleport-only floors. Compare actual hull traces with saved Python probes at mismatches. Resolve Map B's missing models before interpreting its coverage as a generator-only result. Record ladder and gamemode traversal requirements separately. No game test was performed for M1.
