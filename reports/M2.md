# M2: offline NAV generator review fixes and coverage

M2 is implemented and its six offline cases were measured. At slope 0.55 with historical component seeds, Map A generates 31,779 areas in 193.94 seconds and matches 90.506% of the old A-old reference cells, versus 61.950% in M1. This is a different map version, so it is a coverage reference rather than a same-map fidelity score.

Map B content resolution is repaired, but coverage against its installed NAV regressed: recall is 81.997%, down from 88.017% in M1. Floor-supported omissions remain. Unverified fence/drop links also remain. These results are ready for code and native investigation, not a claim of production-ready traversal.

## Implementation and source basis

- Brush entities use class-specific SDK spawn rules. Dust/smoke/precipitation and vehicle/physics-only clips are excluded. `func_lod Solid != 0` means non-solid, despite the key name. Rotating, movelinear, conveyor, rotating buttons, toggle walls, doors and trains use their own flags. `func_button` flag 1 means do-not-move, not non-solid. Brush, reflective glass and monitor honor `Solidity` and `StartDisabled`; generation's special toggle-brush filter remains classname-specific. Unknown brush classes are reported and omitted; there were zero in all measured cases.
- GMA v1-v3 tables are indexed without extraction; only requested payloads are read, with bounds and CRC checks. Lookup follows BSP pakfile, unpacked addons, local/Workshop GMAs, VPKs and loose content. Differing same-path bytes record selected/alternate sources and SHA256s. This priority is explicit and deterministic; it does not establish the engine's live mount order.
- `--slope-limit` defaults to 0.7 and threads through floor movement and jump-area tests, including the +0.1 jump tolerance, plus slope-dependent stair/fence tests. The independent overlap test remains 0.7. Hammer++ arguments in the README use 0.55.
- South/east drop part 1 now begins from the inner owned node row/column, so the first landing probe is 12.5 past the edge; `fromPos` is the node. Part 2 handles unowned actual edge nodes separately. A narrow east landing regression exercises this correction.
- BSP brush sides parse `bevel` and `thin` as separate uint8 fields. Current measured maps have thin=0, so this format correction does not change their geometry.
- Final connection checking distinguishes ordinary steps, drops, fences, stitched jumps and corner helpers. It tries midpoint, drop and multiple positions across the portal. It removes only connections without positive portal width; failed movement samples on other SDK-generated links remain explicitly unverified. No single midpoint failure is treated as proof that an entire connection is blocked.
- `python -I -m navgen.seeds previous.nav [--bsp current.bsp]` prints one seed per weak component, using its largest XY area. With a BSP it tries the center and four interior points, snaps XY to the 25-unit grid and grounds a thin hull from old Z+35.9 to old Z-400. Failed candidates/components are reported on stderr. It neither searches other surfaces nor silently discovers new islands.

## Coverage and graphs

Coverage samples 25-unit XY cell centers with an 18-unit Z tolerance, deduplicating floors rounded to one unit. Precision is the fraction of generated cells matching the reference; recall is the fraction of reference cells matched. Both can change because of geometry, content, seeds and hand-edited reference meshes. Cardinal-transition scores below measure only common coverage and exclude long jump/drop gaps.

|---|---|---|---|---|---|

Construct retains 99.713% recall on the largest reference component (412 of 143,484 cells missed); its 11 unseeded reference islands account for the remaining 15,253 missed cells. The generated graph is one weak/strong component. Adding those islands was not part of this case.

Map B has 98,009 missed reference cells in total. Of 10,000 sampled missed cells, 5,855 still have a floor within 18 units. The main reference component alone misses 95,927 cells. Height bands around -768 and -640 are almost wholly absent even though 298/300 and 297/300 missed-point floor probes succeed. Ground presence does not prove hull clearance or seed reachability. GMA collision, brush solidity and connection changes were applied together; this run does not isolate their individual effects. The installed Map B reference records a different BSP byte size, consistent with repacking, but that fact does not excuse the coverage regression.

### Workshop content audit

All 152 local Workshop GMAs indexed successfully. Map B now resolves all 989 referenced MDLs and all 926 available PHYs (7,895 base convex pieces). M1 missed 514 model files; no referenced MDL is now missing. There are 63 models without PHY, with 222 solid prop instances using the documented bbox fallback. There are 213 differing requested MDL/PHY paths; identical duplicates are not counted as conflicts. Construct has 6 conflicts; Map A has 269.

For example, one cable model's MDL selects an unpacked addon copy (1,748 bytes) over a different Workshop GMA copy (1,456 bytes). Its PHY files have the same size (713 bytes) but different bytes.

These are byte conflicts, not a claim that every duplicate has different collision geometry. Full conflict records and archive errors are in `content_audit`; content priority must be aligned with the intended runtime mounts before treating the generated NAV as an engine-equivalent result.

## Validation, preserved inputs and limits

- 21 unit tests pass (30.901 seconds): original collision, sampling, generation and engine-NAV round trips, plus class solidity, GMA versions/offsets/CRC, content precedence/conflicts, separate brush-side bytes, slope/overlap/jump behavior, component seeds, alternate portal positions and the east-drop landing regression.
- Five CLI invalid slope values (0, -0.1, 1.1, NaN, infinity) fail before input loading and preserve an existing output. Help lists the new option. The actual seed CLI and all six acceptance jobs completed successfully.
- GMod loading, Hammer++ UI, native trace parity and NextBot routes are untested. The NAV remains v16/subversion 0 with `analyzed=0`, no ladders, tactical/visibility/place data or teleport traversal links. Lua/runtime entities and moving collision are not modeled. Missing PHY bbox fallbacks and deterministic mount choices remain approximate.
- Other M1 limitations remain: non-brush model entities are excluded, including NPC-mask stair probes; transformed brush hulls lose per-face surface flags; PHY/terrain contact tolerances and node ordering may differ; fence/overhang adaptations are not byte-equivalent engine behavior. M2 replaces M1's GMA absence and midpoint-pruning limitations but does not resolve these other gaps.

Review entry points: `navgen/collision.py` (`entity_rules`), `navgen/gma.py`, `navgen/bsp.py` (`Content`, brush-side dtype), `navgen/sampling.py` (slope), `navgen/areas.py` (drop edge walk, portal audit), `navgen/seeds.py`, and `tests/test_m2.py`. Native checks should first address the Map B supported-floor omissions and content priority, then retained fence/drop links and routes between seeded Map A floors. Runtime acceptance is outside this milestone.
