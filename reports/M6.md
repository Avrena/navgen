# M6: obstacle-top and drop-link parity

M6 corrects obstacle geometry and split-link inheritance using the Source SDK and read-only disassembly of the installed GMod server DLL. All 52 tests pass, including 10 new rule regressions. Four fresh offline runs include hiding spots. BSP-only Map A has 734 true obstacle-top areas versus the engine's 728, and 1,159 unverified links versus M5's 1,254. Its coverage and directed-transition precision/recall meet or exceed M5. Native acceptance remains open; M6 ran no game.

The final Map A runs use BSP seeds at .55, and .55 plus the 219 historical A-old seeds (257 total). The baseline Git commit is `a6a28c5ebc1117a27e3cce16cb9f208054df6cc6`.

The original comparison script used `OBSTACLE_TOP = 0x2000`. That bit is `NO_MERGE`; the obstacle bit is `0x4000`. Correct baseline counts are BSP 800, seeded 928 and engine 728. The NO_MERGE counts are 1,574 / 1,813 / 1,543. An earlier 1,926 versus 1,543 headline therefore cannot be used as an obstacle-area comparison. `tools/link_audit.py` imports the real constant and otherwise reproduces the run4 probes, endpoint construction and engine-relation checks.

The runtime edits are confined to `navgen/areas.py`:

- Raise an internal obstacle using its start distance for both bounds, then expand to the SDK's ten-unit minimum width. Reproduce EAST's fallthrough into WEST, including the endpoint-height swap. Use NW/NE/SE/SW heights `[start, end, end, start]` for every direction, both when raising and creating areas.
- Stop the creation pass at its first JUMP/OBSTACLE_TOP area. This unusual return is present in the installed binary as well as the SDK. Use the strict XY-circle portal test and the SDK's height-aware point containment for two-node obstacles; include NW/SE Z in area containment during overlap cleanup.
- Permit the five-unit upward tolerance used by `GetNavArea` during initial drop lookup.
- Match `FinishSplitEdit`: incoming links are processed inside the corresponding outgoing-neighbor loop. An empty outgoing side cannot propagate its incoming connections to split children. This removes excess inherited drop links without blanket deletion of failed movement probes.

The original 441 BSP fence/off-engine links contain 456 actually off-engine endpoints: 235 obstacle goals with no engine column, 167 obstacle goals at another height, 39 obstacle starts (37 height / 2 no column), and 15 ground starts (7 height / 8 no column). An earlier count of 126 off-engine ground starts was not reproduced. Downward point traces identify real supporting world brushes and PHY/bounding-box props, including railings, furniture and ledges. A supported surface absent from the reference is not by itself a collision defect. Full point/object evidence is in `baseline-provenance.json` and the corrected aggregate in `baseline-endpoint-summary.json`.

Tracked by exact geometry and the ablation's obstacle identity, the original 441 links now yield: 84 endpoint_changed_or_removed; 241 engine_direct_link; 116 off_engine_mesh. The geometry-only ablation reduced off-engine fence links 441 → 207; adding the confirmed creation exit reduced them to 128. The isolated incoming-split fix then removed the transition-precision regression seen in that intermediate candidate. Pre-split measurements/NAVs and every ablation remain available. The frozen M5 replay has identical serialized area geometry, attributes and directed connections after area IDs are normalized; cloning adjacency sets changes newly created area numbering, so byte identity is not claimed for that replay.

There are still changed shared fence endpoints: the original 719 engine-direct fence links map to 5 endpoint_changed_or_removed; 695 engine_direct_link; 19 off_engine_mesh. These changes follow the verified global rules, but they do not satisfy a literal promise to leave every shared fence untouched. The split rule also changes some formerly shared drop endpoints/connections. `endpoint_changed_or_removed` means no exact geometry counterpart was found; retiled floor is included in that label. `original-link-tracking.json` separately checks the original route points on the final M6 graph. These cases are explicitly staged for native review. No map/reference-specific pruning or runtime dependency on an engine NAV was introduced. Counts close to 728 do not establish exact obstacle parity.

All 12 original BSP off-engine drops start at z=3860.03125 on two real world ledges: brush 8335 (south) and 8340 (north), each 12 units thick and 156 units deep. The reference covers the lower z=3712.03125 floor at those route starts; it also covers portions of the upper ledges elsewhere. Their source surface is supported by BSP collision, not an invented prop floor. The remaining difference involves sampling/partitioning and inherited links, and does not justify deleting the physical ledge. `drop-investigation.json` includes all 20 original drop discrepancies, exact boxes, support planes and successful initial node witnesses where they remain inside the final M5 rectangles.
