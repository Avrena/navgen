# M4: GMod hiding spots and automatic seed-file pickup

M4 adds deterministic hiding spots with IN_COVER/EXPOSED flags and `analyzed=1`, plus automatic `<bsp stem>.navseeds.txt` pickup. All 38 tests pass. Four fresh CLI runs completed; removing hiding spots and restoring `analyzed=0` reproduces each pre-M4 NAV byte for byte, so area geometry, links, attributes and other saved fields are unchanged.

The BSP-only Map A run produces 7,429 spots in 1.98 additional seconds. On the engine mesh's own geometry/topology, the port reproduces all 7,729 positions exactly and matches 7,647/7,729 (98.939%) positions plus complete flag byte within one unit. The 82 unmatched classifications remain a collision-parity limitation.

The historical-seeded Map A mesh has 31,769 areas and 10,529 spots. M4 has not been loaded or tested with bots in game; earlier native M3 tests do not establish native M4 hiding-spot acceptance.

## Analysis mode and implementation

The installed addon sets `nav_quicksave 2` for full generation. Static inspection of the installed x64 DLL confirms that GMod still visits the encounter/sniper states but their functions return early for nonzero quicksave. Visibility is skipped at 2, occupy-time analysis clears both values, the state machine bypasses lighting, and the area custom-analysis method is empty. Full-generation/analysis-only save sets the analyzed byte to 1. M4 implements that measured mode; it does not implement full visibility or Counter-Strike tactical analysis.

Corner selection follows [Valve SDK nav_area.cpp](https://github.com/ValveSoftware/source-sdk-2013/blob/be57e3d01ac7d7aa6a2cacbfef187c0b46616db0/src/game/server/nav_area.cpp): reciprocal non-jump neighbors define uncovered edge extents; both sides must leave a 20-unit corner. JUMP and DONT_HIDE areas have no spots. Positions try the 12.5-unit inset, then Y-center, X-center, both-center, 1-unit and corner fallbacks. Corner Z is preserved, including on sloped areas. Spots less than 30 units apart in 3D within the same area are suppressed. IDs start at zero in saved area order.

Cover uses point rays and mask `0x2400b` (`MASK_NPCSOLID_BRUSHONLY`) with ordinary entity filtering, so active doors/breakables/toggle brushes can provide cover. From spot Z +35.5, an obstructed 20-unit upward ray immediately gives IN_COVER. Otherwise 16 rays extend 100 units radially and another 35.5 units upward; at least eight hits give IN_COVER, otherwise EXPOSED. No walk-through generation filter or player hull is used.

The DLL was read as PE bytes using pefile/Capstone and never loaded or executed. Its SHA256 is `cac5a957b6589c71760b37406b6b99604a49025f67fd6e14c902aa6e1ef63428`. The CNavArea vtable was identified through RTTI. Source hashes, constants and function ranges are in `analysis-source-evidence.json`.

The five cached SDK files were rechecked against the cited commit. Their normalized contents match; raw hashes differ because of newline/trailing whitespace. The hiding routines themselves compare identically as text.

## Seed-file behavior and Hammer++

Without `--seeds`, generation reads `<bsp stem>.navseeds.txt` beside the BSP if present and prints the selected path, or prints that no sidecar was found. `--seeds` overrides that selection; either file supplements the BSP entity seeds. Invalid contents and missing explicit files fail the run. An explicit empty file selects BSP seeds only. The input seed path/hash/source are included in generation JSON.

The README now supplies one Hammer++ step for maps with or without sidecars, after the final BSP-changing compile/packing step:

```text
Executable: .venv\Scripts\python.exe
-I -m navgen "$path\$file.bsp" --game "<game>" --slope-limit 0.55 --out "$path\$file.nav"
```

Unit tests cover absent and automatic files, explicit override precedence, coordinates supplementing BSP seeds, invalid contents, and missing explicit files. The full CLI runs cover absent-sidecar and explicit historical-seed paths. Hammer UI integration remains untested.

## Validation and limits

38 tests pass in 34.002 seconds, including the original 28. New tests cover corner ordering/height, narrow and degenerate inset cases, reciprocal topology and 20-unit thresholds, JUMP/DONT_HIDE, strict 3D spot spacing, overhead/rising-radial cover rays, masks and ordinary entity filtering, deterministic IDs/round-trip serialization, comparison metrics and seed pickup.

Each new NAV is serializer-round-tripped, its BSP size checked, and its pre-M4 content compared byte for byte. Source hashes identify the measured tree.

Remaining limitations are native collision/mount-order and entity-state parity, the 82 engine-topology flag mismatches, existing area-fit/traversal issues and missing runtime/Lua collision. Hiding data availability does not prove that every spot is useful or reachable in the gamemode.
